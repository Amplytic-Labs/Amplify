---
title: Native Installation
description: Run Amplify directly on your machine without containers for development and testing.
---

Running Amplify natively (without Docker or cloud platforms) is the simplest deployment method. This is ideal for local development, quick testing, and scenarios where you don't need containerization.

## Prerequisites

Before installing Amplify natively, ensure you have:

- **Node.js 22+** — Required for the Remix SSR runtime and Wrangler compatibility
  - Download from [nodejs.org](https://nodejs.org/) or use a version manager like `fnm`, `nvm`, or `volta`
- **pnpm** — Amplify's package manager
  - Install via corepack: `corepack enable && corepack prepare pnpm@latest --activate`
  - Or install directly: `npm install -g pnpm`
- **Git** — Required for repository operations and build scripts

### Verifying Prerequisites

```bash
node --version    # Should be v22.x or higher
pnpm --version    # Should be 9.x
git --version     # Any recent version
```

## Installation

### 1. Clone the Repository

```bash
git clone https://github.com/Derek-X-Wang/amplify.git
cd amplify
```

### 2. Install Dependencies

```bash
pnpm install
```

This installs all production and development dependencies using pnpm's efficient content-addressable store.

### 3. Configure Environment Variables

```bash
# Copy the example environment file
cp .env.example .env.local

# Edit .env.local with your API keys
# At minimum, add one AI provider key:
# OPENAI_API_KEY=sk-your-key-here
# or ANTHROPIC_API_KEY=your-key-here
```

### 4. Start Development Server

```bash
pnpm run dev
```

Amplify starts on **http://localhost:5173** with hot module replacement (HMR) enabled. The `dev` command:

1. Runs `node pre-start.cjs` — A pre-start script that validates the environment
2. Starts `remix vite:dev` — The Remix development server with Vite HMR

## Development vs Production Modes

### Development Mode

```bash
pnpm run dev
```

- HMR enabled — instant updates when you edit source files
- Source maps — full debugging in browser DevTools
- Verbose logging — detailed request/response information
- Development-specific error overlays

### Production Preview

To test the production build locally:

```bash
# Build the application
pnpm run build

# Start in production mode
pnpm run preview
```

The `preview` command runs `pnpm run build && pnpm run start`, which:

1. Compiles the Remix application with `remix vite:build`
2. Runs the bindings script (`./bindings.sh`)
3. Starts Wrangler Pages dev with production bindings

This emulates the Cloudflare Pages runtime locally, giving you an accurate preview of how Amplify behaves in production.

### Platform-Specific Start Commands

The `start` script automatically detects your platform:

```bash
pnpm run start
```

- **Unix/macOS**: `bindings=$(./bindings.sh) && wrangler pages dev ./build/client $bindings`
- **Windows**: `wrangler pages dev ./build/client` (bindings script not supported on Windows natively)

If you're on Windows and need bindings, set environment variables directly:

```bash
# PowerShell
$env:OPENAI_API_KEY="sk-your-key"
$env:ANTHROPIC_API_KEY="your-key"
pnpm run start:windows
```

## Environment Variable Configuration

Amplify uses a layered environment configuration:

1. **`.env`** — Base configuration (committed to Git)
2. **`.env.local`** — Local overrides with API keys (never committed)
3. **`.env.production`** — Production-specific overrides

### Key Environment Variables

| Variable | Purpose | Default |
| --- | --- | --- |
| `PORT` | Application port | `5173` |
| `NODE_ENV` | Runtime mode | `development` |
| `VITE_LOG_LEVEL` | Logging verbosity | `debug` |
| `DEFAULT_NUM_CTX` | Context window for local models | `32768` |
| `OPENAI_API_KEY` | OpenAI provider key | — |
| `ANTHROPIC_API_KEY` | Anthropic provider key | — |
| `OLLAMA_API_BASE_URL` | Local Ollama endpoint | `http://127.0.0.1:11434` |

### Local Provider Configuration

When running Ollama or LM Studio locally, use `127.0.0.1` instead of `localhost`:

```bash
# .env.local
OLLAMA_API_BASE_URL=http://127.0.0.1:11434     # NOT localhost
LMSTUDIO_API_BASE_URL=http://127.0.0.1:1234    # NOT localhost
```

This avoids IPv6 resolution issues where `localhost` may resolve to `::1` instead of `127.0.0.1`, causing connection failures.

## Port Configuration

Amplify defaults to port **5173**, matching Vite's convention. To change the port:

```bash
# Via environment variable
PORT=8080 pnpm run dev

# Or in .env.local
PORT=8080
```

The port is used by:

- The Remix Vite dev server (development mode)
- Wrangler Pages dev (production preview mode)
- Docker deployments (mapped via `ports` configuration)

## Production Build Process

The production build creates optimized bundles for both client and server:

```bash
pnpm run build
```

This runs `remix vite:build`, which produces:

```text
build/
├── client/           # Static client bundle
│   ├── assets/       # JS, CSS, and other static assets
│   └── index.html    # HTML shell for SSR
└── server/           # Server-side rendering entry
    └── index.js      # Remix server bundle
```

### Build Output Details

- **Client bundle**: Minified JavaScript and CSS with content hashes for cache busting
- **Server bundle**: Remix SSR module that runs on Wrangler/Cloudflare Workers
- **Assets**: Images, fonts, and other static resources

### Memory Requirements

The build process can be memory-intensive. If you encounter OOM errors:

```bash
# Increase Node.js heap size
NODE_OPTIONS=--max-old-space-size=4096 pnpm run build
```

## Common Issues

### Wrangler Types Errors

If TypeScript complains about Cloudflare bindings:

```bash
# Regenerate Wrangler types
pnpm run typegen
```

This updates `worker-configuration.d.ts` with the latest type definitions.

### Husky Git Hooks

Husky is disabled in CI environments (`HUSKY=0`). If you want to skip hooks locally:

```bash
HUSKY=0 pnpm run build
```

### Pnpm Lockfile Issues

If dependencies fail to install:

```bash
# Clear pnpm store and reinstall
pnpm store prune
pnpm install --frozen-lockfile
```

### Wrangler Authentication

For `pnpm run deploy` or `pnpm run preview`, Wrangler needs authentication:

```bash
# Login to Cloudflare
wrangler login

# Or use an API token
export CLOUDFLARE_API_TOKEN=your-token
```
