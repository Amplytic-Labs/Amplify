## White Screen Issues

### App loads to a blank white screen

**Cause:** Most white screen issues are caused by missing or invalid API keys, or JavaScript errors that prevent the app from rendering.

**Solutions:**

1. Open browser DevTools (F12 / Cmd+Option+I) and check the Console tab for errors
2. Verify your API key is set correctly (see [API Key Configuration](#api-key-configuration-problems))
3. Clear browser cache and localStorage: `localStorage.clear()` in the Console
4. If using the desktop app, check `~/Library/Logs/Amplify/` (macOS) for crash logs

### White screen after update

**Cause:** Stale IndexedDB data from a previous version may conflict with the new schema.

**Solutions:**

1. Clear IndexedDB data: DevTools → Application → IndexedDB → Delete all databases
2. Clear localStorage: `localStorage.clear()` in Console
3. Refresh the page

## API Key Configuration Problems

### "Missing API key" error

**Cause:** The required provider API key is not configured in environment variables or the Settings UI.

**Solutions:**

1. For **cloud deployment**: Set the API key in your hosting platform's environment variables (e.g., Cloudflare Workers `wrangler.toml`, Vercel env vars)
2. For **local development**: Create a `.env` file in the project root:
   ```bash
   OPENAI_API_KEY=sk-...
   ANTHROPIC_API_KEY=sk-ant-...
   GOOGLE_GENERATIVE_AI_API_KEY=...
   ```
3. For **desktop app**: API keys can be configured in the Settings UI

### "Invalid API key" or 401 errors

**Cause:** The key is malformed, expired, or lacks the required permissions.

**Solutions:**

1. Verify the key format matches the provider's expected format
2. Check that the key has not been revoked or expired
3. Ensure the key has the required model access (e.g., GPT-4 requires a paid tier key)
4. Test the key directly with the provider's API using curl:
   ```bash
   curl https://api.openai.com/v1/models \
     -H "Authorization: Bearer $OPENAI_API_KEY"
   ```

### Multiple provider keys conflicting

**Cause:** Amplify supports multiple AI providers simultaneously. If multiple keys are set, the system uses the one matching the selected model.

**Solution:** Set only the key for the provider you intend to use, or verify the model selection matches the key you've configured.

## WebContainer Errors

### "SharedArrayBuffer is not defined"

**Cause:** Missing or incorrect Cross-Origin isolation headers. WebContainers require COOP/COEP headers to enable SharedArrayBuffer.

**Solutions:**

1. Ensure your server sets these response headers:
   ```
   Cross-Origin-Embedder-Policy: credentialless
   Cross-Origin-Opener-Policy: same-origin
   Cross-Origin-Resource-Policy: cross-origin
   ```
2. For **Cloudflare Pages**: These headers must be set via a `_headers` file in the public directory
3. For **Vite dev server**: Headers are configured in `vite.config.ts` (already set by default)
4. For **desktop app**: COOP/COEP headers are not required (WebContainer runs natively)

### WebContainer fails to boot

**Cause:** Browser incompatibility or network restrictions.

**Solutions:**

1. Use a supported browser: Chrome 89+, Edge 89+, Safari 15.2+, Firefox 79+
2. Check that no corporate proxy or firewall is blocking `webcontainer-api.io`
3. Disable browser extensions that modify page security policies
4. Try the desktop app, which avoids COOP/COEP restrictions entirely

### "WebContainer preview not loading"

**Cause:** Preview iframe blocked by security policies or CORS.

**Solutions:**

1. Check browser DevTools Network tab for blocked requests to `*.local-credentialless.webcontainer-api.io`
2. Ensure no Content Security Policy (CSP) is blocking iframe sources
3. Disable ad blockers or privacy extensions that may block cross-origin resources

## Provider Connection Issues

### "Connection refused" or network errors

**Cause:** API provider endpoints are unreachable.

**Solutions:**

1. Verify your internet connection and that the provider's API is accessible
2. Check for proxy/firewall restrictions blocking the provider's domain
3. For self-hosted models (Ollama, LM Studio): ensure the server is running and the URL/port is correct
4. For LM Studio specifically: ensure CORS is enabled in LM Studio settings, or use the Amplify desktop app to avoid CORS restrictions

### "CORS error" with local models

**Cause:** Browser security prevents cross-origin requests to local model servers.

**Solutions:**

1. Enable CORS in your local model server settings (Ollama, LM Studio)
2. Use the Amplify **desktop app** — it bypasses CORS restrictions entirely since requests are made from the main process, not the renderer
3. Set up a reverse proxy (e.g., nginx) to add CORS headers to local model responses

### Response streaming interrupted

**Cause:** Network instability or server-side timeout.

**Solutions:**

1. Increase the request timeout in your hosting configuration
2. Check for rate limiting on the provider's API
3. Verify that your cloud hosting platform supports streaming responses (some platforms buffer responses)

## Deployment Troubleshooting

### Cloudflare Workers deployment fails

**Cause:** Cloudflare Workers have specific constraints on bundle size and runtime APIs.

**Solutions:**

1. Ensure the `wrangler.toml` compatibility date is set correctly
2. Check that the bundle size stays within Workers limits (free tier: 1MB, paid: 10MB)
3. Verify all environment variables are set in the Workers dashboard

### Vercel deployment shows white screen

**Cause:** Missing environment variables or incorrect build configuration.

**Solutions:**

1. Set all required API keys in Vercel's Environment Variables settings
2. Ensure the build command is correct: `npm run build`
3. Check Vercel's deployment logs for build errors

### Docker deployment COOP/COEP issues

**Cause:** The reverse proxy (nginx, Caddy) may strip or not set the required headers.

**Solutions:**

1. Add the headers to your reverse proxy configuration:
   ```nginx
   add_header Cross-Origin-Embedder-Policy "credentialless";
   add_header Cross-Origin-Opener-Policy "same-origin";
   add_header Cross-Origin-Resource-Policy "cross-origin";
   ```
2. Note: `add_header` in nginx only applies to successful responses by default. Use `add_header ... always;` to include error responses

## Rate Limit Exceeded

### "429 Too Many Requests"

**Cause:** The AI provider's rate limit has been exceeded for your API key.

**Solutions:**

1. **Wait and retry** — Most rate limits reset after a short period (1 minute to 1 hour depending on the provider)
2. **Reduce frequency** — Decrease the number of concurrent chat sessions
3. **Upgrade your plan** — Higher-tier API keys often have increased rate limits
4. **Switch providers** — Configure a fallback provider in Settings

### Token rate limit exceeded

**Cause:** Per-minute or per-day token limits on the provider's API.

**Solutions:**

1. Use models with lower token costs (e.g., GPT-3.5 instead of GPT-4)
2. Reduce the `maxLLMSteps` setting (default: 5) to limit tool call iterations
3. Split large tasks into smaller chat sessions

## Debug Tools and Event Logs

### Browser DevTools Console

The Console tab shows:
- `[mcp-service]` — MCP connection and tool registration events
- `[UserProfileVectorStore]` — Vector store initialization and search events
- `[ProjectContextStore]` — Project context operations
- `[native-tools]` — Native tool execution events

### IndexedDB Inspector

DevTools → Application → IndexedDB shows:
- `amplify_vector_stores` — All Orama database snapshots
- Individual store entries with search metadata

### localStorage Inspector

DevTools → Application → Local Storage shows:
- `mcp_settings` — MCP configuration and maxLLMSteps
- Provider-specific settings and API key configurations
- Session and project metadata

### Network Tab

Monitor outgoing requests to:
- `/api/chat` — Main AI streaming endpoint
- `/api/mcp-update-config` — MCP configuration updates
- `/api/mcp-check` — MCP server availability checks
- `/api/web-search` — Web search tool requests
- Provider API endpoints (api.openai.com, api.anthropic.com, etc.)

### Desktop App Logs

On macOS, logs are stored at `~/Library/Logs/Amplify/main.log`. These include:
- Electron main process events
- Auto-update check results
- Protocol handler routing decisions
- Cookie persistence operations

## Common Error Messages

| Error Message                                  | Cause                               | Solution                                    |
|------------------------------------------------|--------------------------------------|---------------------------------------------|
| `SharedArrayBuffer is not defined`            | Missing COOP/COEP headers           | Add cross-origin isolation headers          |
| `Cannot read properties of undefined`          | WebContainer not initialized         | Check browser compatibility and headers     |
| `MCP server "X" unavailable`                   | Server connection failed             | Verify URL/command and server availability  |
| `Missing API key`                              | No provider key configured           | Set key in env vars or Settings UI          |
| `429 Too Many Requests`                        | Provider rate limit exceeded         | Wait, reduce usage, or upgrade API tier     |
| `User context search not available on server`  | Vector store called server-side      | This is expected; tool only works client-side |
| `Vector store persistence failed`               | IndexedDB write error                | Clear IndexedDB, check browser storage quota |
| `CORS_ERROR: LM Studio server is blocking`    | LM Studio CORS not enabled           | Enable CORS in LM Studio or use desktop app |
| `Error updating MCP config`                    | Invalid MCP server configuration    | Check config JSON against transport schemas |
| `WebContainer boot timeout`                    | Browser can't initialize WebContainer| Try desktop app or check browser support    |
