# Skills

Skills are **procedural markdown instruction files** that teach the AI how to handle specific tasks. Each skill is a self-contained document with YAML frontmatter and structured markdown content that the AI reads and follows when the skill is activated.

## What Are Skills?

A skill is a `SKILL.md` file that provides step-by-step guidance for a particular domain or task type. When the AI encounters a relevant request, it loads the skill's content and follows its instructions — ensuring consistent, expert-level results.

Skills use **YAML frontmatter** for metadata:

```yaml
---
name: html-page
description: >
  Use this skill whenever the user asks to create a standalone HTML page,
  single-file website, or simple web page without a framework.
  Triggers: "create an HTML page", "make a landing page",
  "build a simple webpage", "single HTML file", "static page".
---
```

The frontmatter includes:
- `name` — unique identifier
- `description` — when and how to use the skill, including trigger phrases
- `priority` — optional score for token budget allocation
- `tags` — optional categorization tags
- `version` — optional schema version

## Core Skills

Amplify ships with built-in core skills for common development tasks:

### api-integration

Guides the AI through creating API integrations — REST clients, GraphQL queries, authentication flows, and error handling patterns.

### react-best-practices

Enforces React best practices — functional components, proper hooks usage, state management patterns, and performance optimization.

### frontend-design

Professional frontend design skill covering responsive layouts, accessibility (WCAG 2.1 AA), 8px grid system, semantic HTML, and proper component states (loading, empty, error, success).

### docx

Document creation skill for generating DOCX files with proper formatting, tables, headers, and styling using Amplify's markdown-to-docx pipeline.

## Skill Loading and Auto-Discovery

Skills are loaded and discovered through the **SkillLoader** system:

1. **Core skills** — loaded from `app/lib/skills/` on startup
2. **Design skills** — loaded from `design/skills/` with YAML frontmatter support
3. **User skills** — loaded from `user_skills/` directory (custom skills you install)
4. **Design systems** — loaded separately from `design/design-systems/`

Each skill directory contains:
- `SKILL.md` — the main instruction file (required)
- `manifest.json` — optional metadata in JSON format (overrides frontmatter)
- Additional resource files (templates, examples, etc.)

The SkillLoader:
- Parses YAML frontmatter from `SKILL.md` for metadata
- Falls back to `manifest.json` if available
- Validates manifests against the `SkillManifestSchema` (Zod)
- Handles both directory-based and single-file skill formats

## Skill Marketplace

Amplify includes a **Skill Marketplace** for discovering and installing community skills:

- Browse available skills by category (coding, design, data, writing, general)
- Each skill has a manifest with: `name`, `version`, `author`, `description`, `category`, `permissions`, `estimatedTokens`, `verified`, `rating`, `installCount`
- Skills are packaged as `.skill` bundles (ZIP files containing `manifest.json`, `SKILL.md`, and resources)
- Install by uploading a bundle — it's extracted to `user_skills/` and auto-loaded
- Uninstall removes the skill directory and deregisters it
- Verified skills have been reviewed for quality and safety

Manifest validation enforces:
- SemVer versioning (e.g., `1.0.0`)
- Required fields: `name`, `version`, `author`, `description`, `category`
- Permission declarations: `filesystem`, `network`, `shell`
- Rating bounds (0–5) and non-negative install counts

## Progressive Loading

Skills are loaded progressively to manage token budgets:

1. **Metadata phase** — only `name`, `label`, `description` are loaded (tiny payload)
2. **Body phase** — full `SKILL.md` content is loaded when the skill is activated for a task
3. **Resources phase** — additional files (templates, examples) are loaded only when referenced

This means the AI can see a catalog of available skills without consuming the full content of every skill. Content is loaded on-demand when the planner marks a skill as `requiredSkills` for a plan point, or when the AI determines a skill is relevant to the current task.

The token budget system:
- Skills are filtered by available token space (approx 4 chars per token)
- Higher-priority skills are included first
- Project-specific skill filters can restrict which skills are available per project
