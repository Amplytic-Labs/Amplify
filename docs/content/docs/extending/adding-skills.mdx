---
title: Adding a New Skill
description: How to create and register custom skills in Amplify's skill system
---

Skills are the primary way to extend Amplify's behavior. A skill provides step-by-step instructions that the AI follows when a specific type of task is triggered. Skills are auto-discovered by the `SkillLoader` at startup.

## Skill Directory Structure

Amplify supports three skill locations, each serving a different purpose:

| Directory | Purpose | Who Manages |
|-----------|---------|-------------|
| `app/lib/skills/` | Core skills bundled with the app | Amplify team |
| `design/skills/` | Bundled community/design skills | Amplify team |
| `user_skills/` | User-created custom skills | You |

Each skill is a directory containing a `SKILL.md` file and optional supporting files:

```
user_skills/
  my-custom-skill/
    SKILL.md           # Required: skill instructions with YAML frontmatter
    manifest.json       # Optional: marketplace metadata
    references/         # Optional: reference docs the AI can consult
      api-docs.md
      style-guide.md
    scripts/            # Optional: helper scripts
      setup.sh
    assets/             # Optional: images, templates, etc.
      template.html
```

## Creating a Skill

### 1. Create the Skill Directory

```bash
mkdir -p user_skills/my-custom-skill
```

### 2. Write SKILL.md with YAML Frontmatter

The `SKILL.md` file is the core of every skill. It uses YAML frontmatter for metadata and Markdown for the instructions the AI follows:

```markdown
---
name: my-custom-skill
description: >
  Use this skill whenever the user asks to create a custom data visualization
  dashboard. Triggers: "build a dashboard", "create a chart page", "data viz",
  "analytics dashboard", "monitoring dashboard". Do NOT use for single
  components (use react-component skill instead).
---

# Custom Dashboard Skill

You are an expert at creating data visualization dashboards. Follow these guidelines strictly.

## Template

This skill uses the **Vite Shadcn** template.

- **Injection**: Call `inject_template` with the `vite-shadcn` template name.

## Step-by-Step Workflow

### Step 1: Analyze Requirements

Before writing any code:

1. Identify the data sources and metrics to display
2. Determine the dashboard layout (grid, tabs, sidebar)
3. List all chart types needed (line, bar, pie, heatmap)
4. Decide on real-time vs. static data

### Step 2: Inject Template

Call `inject_template` with the chosen template. Wait for injection to complete.

### Step 3: Request Capabilities

Call `request_capabilities` with `capability: 'app_builder'`.

### Step 4: Build Dashboard Components

Create each dashboard section as a separate component:

```
src/
  components/
    dashboard/
      DashboardLayout.tsx
      MetricCard.tsx
      ChartPanel.tsx
      DataTable.tsx
  pages/
    Dashboard.tsx
```

### Step 5: Integrate Charts

Use Recharts for data visualization:

- Always include legends, tooltips, and responsive sizing
- Use consistent color palette across all charts
- Support loading and error states

### Step 6: Add Realistic Data

NEVER use empty arrays. Every dashboard must show:
- 5-10 realistic data points per chart
- Time-series data with proper timestamps
- Aggregation summaries

## Design Rules

1. Use Tailwind CSS for all styling
2. Support dark mode with `dark:` variants
3. Mobile-responsive: stack cards vertically on small screens
4. One accent color for highlights, neutral for everything else
5. Cards: 12px radius, 1px border, 20px padding

## Critical Rules

1. ALWAYS use TypeScript with proper interfaces
2. NEVER use inline styles
3. ALWAYS handle loading and error states
4. ALWAYS make dashboards responsive
```

### 3. Frontmatter Properties

The YAML frontmatter supports these properties:

| Property | Required | Description |
|----------|----------|-------------|
| `name` | Yes | Unique skill identifier (lowercase, hyphenated) |
| `description` | Yes | Description including trigger phrases and scope |

**Writing effective descriptions:** The `description` field is critical because the AI uses it to decide which skill to activate. Include:

- **Trigger phrases** — words that should activate this skill
- **Scope boundary** — what this skill does NOT cover
- **Context** — when the skill is appropriate

Example:

```yaml
description: >
  Use this skill whenever the user asks to set up a Supabase backend for
  their project. Triggers: "add Supabase", "Supabase backend", "database
  setup", "auth with Supabase". Also use when the user mentions realtime,
  storage, or edge functions in context of Supabase.
  Do NOT use for generic database design (use sql-backend skill instead).
```

### 4. Optional: Create manifest.json

For skills intended for the marketplace, create a `manifest.json`:

```json
{
  "name": "my-custom-skill",
  "version": "1.0.0",
  "description": "Create data visualization dashboards",
  "author": "your-name",
  "tags": ["dashboard", "visualization", "charts", "analytics"],
  "category": "frontend",
  "homepage": "https://github.com/you/my-custom-skill",
  "license": "MIT"
}
```

The `SkillLoader` tries `manifest.json` first; if not found, it falls back to parsing the YAML frontmatter from `SKILL.md`.

### 5. Optional: Add Supporting Files

#### References Directory

Place reference documentation in `references/`:

```
references/
  api-docs.md        # API documentation the AI can consult
  style-guide.md     # Design guidelines
  best-practices.md  # Coding conventions
```

#### Scripts Directory

Helper scripts in `scripts/` can automate setup tasks:

```bash
#!/bin/bash
# scripts/setup.sh
npm install recharts date-fns
```

#### Assets Directory

Templates, images, or other resources in `assets/`:

```
assets/
  dashboard-template.tsx    # Starter template
  color-palette.json        # Pre-defined color tokens
```

## Auto-Discovery Mechanism

The `SkillLoader` automatically discovers skills at startup:

1. Scans `app/lib/skills/` for core skills
2. Scans `design/skills/` for bundled skills (with YAML frontmatter support)
3. Scans `user_skills/` for user-created skills
4. For each directory found, reads `SKILL.md` and optionally `manifest.json`
5. Registers skills in an internal `Map<string, Skill>`

The loader follows this progressive loading pattern:

| Phase | What's Loaded | When |
|-------|--------------|------|
| **Metadata** | `id`, `label`, `description` | At startup — always loaded |
| **Body** | Full `SKILL.md` content | When the AI activates the skill |
| **Resources** | `references/`, `scripts/`, `assets/` | Only when needed |

This means the AI sees a list of available skills (names + descriptions) in every prompt, but the full skill instructions are only loaded when the AI decides to use a particular skill.

## Token Budget for Skill Context

Skills consume tokens from the AI's context window. The `SkillLoader.getSkills()` method accepts a `tokenBudget` parameter that limits how many skill descriptions are included:

```ts
// Only include skills whose metadata fits within ~500 tokens
const skills = skillLoader.getSkills(500);
```

The budget is calculated as approximately 4 characters per token. Skills are included in order until the budget is exhausted. This prevents skill metadata from overwhelming the prompt.

Keep your skill `name` and `description` concise to maximize the number of skills that can fit in the context window.

## Project-Specific Skills

Skills can be scoped to specific projects using the `projectSkills` store. When a project has defined skill IDs, only those skills are offered to the AI:

```ts
// In the planner/context builder:
const skills = skillLoader.getSkills(tokenBudget, projectId);
```

If `projectId` is provided and the project has a skill list, only matching skills are returned. Otherwise, all skills are available.

## Installing Skills from Bundles

Skills can be packaged as `.skill` bundles (ZIP archives) and installed via the marketplace or programmatically:

```ts
const loader = SkillLoader.getInstance();
const manifest = await loader.installSkill('/path/to/skill-bundle.skill');
```

A valid `.skill` bundle must contain:
- `SKILL.md` — required
- `manifest.json` — required for marketplace listing
- Optional: `references/`, `scripts/`, `assets/`

The bundle is extracted to `user_skills/{skill-name}/` and the registry is refreshed.

## Uninstalling Skills

```ts
const loader = SkillLoader.getInstance();
await loader.uninstallSkill('my-custom-skill');
```

This removes the skill directory from `user_skills/` and deletes it from the registry.

## Full Example: Creating a Skill from Scratch

Here's a complete walkthrough for creating a "SQL Backend" skill:

```bash
# 1. Create the directory
mkdir -p user_skills/sql-backend/references

# 2. Create SKILL.md
cat > user_skills/sql-backend/SKILL.md << 'EOF'
---
name: sql-backend
description: >
  Use this skill whenever the user asks to design or build a SQL database
  backend. Triggers: "database schema", "SQL backend", "database design",
  "create tables", "ORM setup", "migration". Also use when the user mentions
  PostgreSQL, MySQL, or SQLite setup.
  Do NOT use for Supabase-specific tasks (use supabase-backend skill instead).
  Do NOT use for NoSQL databases (use nosql-backend skill instead).
---

# SQL Backend Skill

You are an expert database architect. Design and implement SQL backends following these guidelines.

## Template

Use the **Vite React** or **Remix TypeScript** template depending on whether the backend is standalone or integrated.

## Step-by-Step Workflow

### Step 1: Analyze Requirements

1. Identify entities and relationships from the user's description
2. Determine normalization level (usually 3NF)
3. List all required indexes
4. Decide on the ORM (Prisma, Drizzle, or raw SQL)

### Step 2: Inject Template

Call `inject_template` with the chosen template.

### Step 3: Request Capabilities

Call `request_capabilities` with `capability: 'app_builder'`.

### Step 4: Design Schema

Create the schema file:

```
src/
  db/
    schema.prisma        # If using Prisma
    migrations/          # Migration files
    seed.ts              # Seed data
```

### Step 5: Define Models

Each model must include:
- Primary key (UUID or auto-increment)
- Timestamps (createdAt, updatedAt)
- Proper relations with cascade rules
- Indexes on frequently queried fields

### Step 6: Add Seed Data

Always include realistic seed data:
- 10-20 rows per table
- Realistic names, emails, dates
- Cover edge cases (NULL values, long strings)

## Design Rules

1. ALWAYS use UUIDs for primary keys in distributed systems
2. NEVER use raw string interpolation in SQL queries
3. ALWAYS add createdAt/updatedAt timestamps
4. ALWAYS define foreign key constraints with ON DELETE rules
5. ALWAYS create indexes for join columns and filter fields

## Critical Rules

1. NEVER store plaintext passwords
2. ALWAYS validate input before database operations
3. ALWAYS use transactions for multi-table operations
4. ALWAYS handle connection pooling in production
EOF

# 3. Create reference documentation
cat > user_skills/sql-backend/references/prisma-patterns.md << 'EOF'
# Common Prisma Patterns

## One-to-Many Relations
```prisma
model User {
  id        String   @id @default(uuid())
  posts     Post[]
}

model Post {
  id        String   @id @default(uuid())
  author    User     @relation(fields: [authorId], references: [id], onDelete: Cascade)
  authorId  String
}
```

## Soft Deletes
```prisma
model Document {
  id        String    @id @default(uuid())
  deletedAt DateTime?
  // Filter globally: @@where(deletedAt: null)
}
```
EOF

# 4. Skill is now auto-discovered
# Restart the server or call SkillLoader.getInstance().loadSkills()
```

The skill will appear in the AI's available skill list and activate when trigger phrases are detected in the user's message.
