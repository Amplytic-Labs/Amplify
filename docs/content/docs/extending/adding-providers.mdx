---
title: Adding a New AI Provider
description: How to integrate a new LLM provider into Amplify's provider system
---

Amplify uses a modular provider system that makes it straightforward to add support for new AI providers. Every provider extends a common `BaseProvider` class and is automatically discovered by the `LLMManager`.

## Overview

The provider system follows this architecture:

- **`BaseProvider`** — abstract class that all providers extend
- **`LLMManager`** — singleton that discovers and registers all providers from `registry.ts`
- **`registry.ts`** — barrel file that imports and exports all provider classes
- Each provider lives in its own file under `app/lib/modules/llm/providers/`

## Step-by-Step Guide

### 1. Create the Provider File

Create a new file at `app/lib/modules/llm/providers/your-provider.ts`:

```ts
import { BaseProvider } from '~/lib/modules/llm/base-provider';
import type { ModelInfo } from '~/lib/modules/llm/types';
import type { IProviderSetting } from '~/types/model';
import { createOpenAI } from '@ai-sdk/openai';

export default class YourProvider extends BaseProvider {
  name = 'YourProvider'; // Display name shown in the UI

  // Optional: link where users can get an API key
  getApiKeyLink = 'https://your-provider.com/api-keys';

  config = {
    apiTokenKey: 'YOUR_PROVIDER_API_KEY', // Env var name for the API key
    baseUrlKey: 'YOUR_PROVIDER_API_BASE_URL', // Env var name for the base URL (optional)
    baseUrl: 'https://api.your-provider.com/v1', // Default base URL (optional)
  };

  // Models that are always available, even without an API key
  staticModels: ModelInfo[] = [
    {
      name: 'your-model-small',
      label: 'Your Model Small',
      provider: 'YourProvider',
      maxTokenAllowed: 32000,
      maxCompletionTokens: 4096,
    },
    {
      name: 'your-model-large',
      label: 'Your Model Large',
      provider: 'YourProvider',
      maxTokenAllowed: 128000,
      maxCompletionTokens: 8192,
    },
  ];

  // Optional: fetch available models dynamically from the provider's API
  async getDynamicModels(
    apiKeys?: Record<string, string>,
    settings?: IProviderSetting,
    serverEnv?: Record<string, string>,
  ): Promise<ModelInfo[]> {
    const { apiKey } = this.getProviderBaseUrlAndKey({
      apiKeys,
      providerSettings: settings,
      serverEnv: serverEnv as any,
      defaultBaseUrlKey: 'YOUR_PROVIDER_API_BASE_URL',
      defaultApiTokenKey: 'YOUR_PROVIDER_API_KEY',
    });

    if (!apiKey) {
      throw `Missing Api Key configuration for ${this.name} provider`;
    }

    const { baseUrl } = this.getProviderBaseUrlAndKey({
      apiKeys,
      providerSettings: settings,
      serverEnv: serverEnv as any,
      defaultBaseUrlKey: 'YOUR_PROVIDER_API_BASE_URL',
      defaultApiTokenKey: 'YOUR_PROVIDER_API_KEY',
    });

    const response = await fetch(`${baseUrl}/models`, {
      headers: { Authorization: `Bearer ${apiKey}` },
      signal: this.createTimeoutSignal(),
    });

    const res = (await response.json()) as any;
    const staticModelIds = this.staticModels.map((m) => m.name);

    // Filter out models already in staticModels
    const data = res.data.filter(
      (model: any) => model.object === 'model' && !staticModelIds.includes(model.id),
    );

    return data.map((m: any) => ({
      name: m.id,
      label: `${m.id}`,
      provider: this.name,
      maxTokenAllowed: m.context_window || 32000,
      maxCompletionTokens: 4096,
    }));
  }

  // Required: create a LanguageModel instance for the AI SDK
  getModelInstance(options: {
    model: string;
    serverEnv: Env;
    apiKeys?: Record<string, string>;
    providerSettings?: Record<string, IProviderSetting>;
  }): any {
    const { model, serverEnv, apiKeys, providerSettings } = options;

    const { apiKey, baseUrl } = this.getProviderBaseUrlAndKey({
      apiKeys,
      providerSettings: providerSettings?.[this.name],
      serverEnv: serverEnv as any,
      defaultBaseUrlKey: 'YOUR_PROVIDER_API_BASE_URL',
      defaultApiTokenKey: 'YOUR_PROVIDER_API_KEY',
    });

    if (!apiKey) {
      throw new Error(`Missing API key for ${this.name} provider`);
    }

    // If your provider is OpenAI-compatible, use createOpenAI:
    const client = createOpenAI({
      baseURL: baseUrl || 'https://api.your-provider.com/v1',
      apiKey,
    });

    return client(model);
  }
}
```

### 2. Required Properties

Every provider **must** define these properties:

| Property | Type | Description |
|----------|------|-------------|
| `name` | `string` | Display name for the provider (e.g., `"OpenAI"`, `"Groq"`) |
| `staticModels` | `ModelInfo[]` | List of models always shown, even without API keys |
| `config` | `ProviderConfig` | Object with `apiTokenKey` and optionally `baseUrlKey`/`baseUrl` |

### 3. Optional Methods

| Method | Returns | Description |
|--------|---------|-------------|
| `getDynamicModels()` | `Promise<ModelInfo[]>` | Fetches live model list from the provider API |
| `getModelInstance()` | `LanguageModel` | Creates an AI SDK model instance for use in streaming |
| `getApiKeyLink` | `string` | URL where users can obtain an API key |
| `icon` | `string` | Icon identifier for the UI |

### 4. Register in the Registry

Add your provider to `app/lib/modules/llm/registry.ts`:

```ts
import YourProvider from './providers/your-provider';

export {
  // ... existing providers
  YourProvider,
};
```

The `LLMManager` automatically discovers all exports from `registry.ts` that extend `BaseProvider` and registers them at startup.

### 5. Add the Environment Variable

Add your API key variable to `.env.example` (or `.env.local`):

```bash
YOUR_PROVIDER_API_KEY=your-api-key-here
```

If your provider uses a custom base URL, also add:

```bash
YOUR_PROVIDER_API_BASE_URL=https://api.your-provider.com/v1
```

### 6. Update Vite Configuration (if using a custom base URL)

If your provider exposes a base URL environment variable, add it to the `envPrefix` array in `vite.config.ts` so Vite exposes it to the client:

```ts
envPrefix: [
  'VITE_',
  // ... existing entries
  'YOUR_PROVIDER_API_BASE_URL',
],
```

### 7. Update Docker Configuration

Add your environment variables to `docker-compose.yaml` in both the `app-prod` and `app-dev` services:

```yaml
environment:
  - YOUR_PROVIDER_API_KEY=${YOUR_PROVIDER_API_KEY}
  - YOUR_PROVIDER_API_BASE_URL=${YOUR_PROVIDER_API_BASE_URL}  # if applicable
```

### 8. Add a Provider Icon

1. Add an SVG icon to `icons/YourProvider.svg`
2. Copy the same icon to `public/icons/YourProvider.svg`

Icons should be simple, monochrome SVGs that work at small sizes (16–24px).

### 9. Verify Registration

Your provider is now automatically included in `PROVIDER_LIST` (defined in `app/utils/constants.ts`), which is populated by `LLMManager.getAllProviders()`. No manual addition needed — the manager iterates all registered providers.

## OpenAI-Compatible Providers

Many providers (Groq, Together, Deepseek, etc.) use an OpenAI-compatible API. For these, you can use the `createOpenAI` helper from `@ai-sdk/openai` with a custom `baseURL`:

```ts
getModelInstance(options) {
  const { apiKey, baseUrl } = this.getProviderBaseUrlAndKey({ ... });

  const openai = createOpenAI({
    baseURL: baseUrl,
    apiKey,
  });

  return openai(model);
}
```

For providers that don't follow the OpenAI API format, use the appropriate AI SDK package (e.g., `@ai-sdk/google` for Google, `@ai-sdk/anthropic` for Anthropic).

## Docker URL Resolution

If your provider uses a `localhost` or `127.0.0.1` base URL (like Ollama or LM Studio), the `BaseProvider` automatically rewrites these to `host.docker.internal` when running inside Docker. This ensures local providers remain reachable from the containerized app.

## ModelInfo Fields

Each `ModelInfo` entry has these fields:

| Field | Type | Required | Description |
|-------|------|----------|-------------|
| `name` | `string` | Yes | Model ID used in API calls (e.g., `"gpt-4o"`) |
| `label` | `string` | Yes | Human-readable name shown in the UI |
| `provider` | `string` | Yes | Must match the provider's `name` property |
| `maxTokenAllowed` | `number` | Yes | Maximum context window in tokens |
| `maxCompletionTokens` | `number` | Yes | Maximum output tokens the model can generate |
| `tpm` | `number` | No | Tokens per minute rate limit |
| `rpm` | `number` | No | Requests per minute rate limit |

## Full Example: Minimal Provider

Here's a minimal provider without dynamic model discovery:

```ts
import { BaseProvider } from '~/lib/modules/llm/base-provider';
import type { ModelInfo } from '~/lib/modules/llm/types';
import { createOpenAI } from '@ai-sdk/openai';

export default class MinimalProvider extends BaseProvider {
  name = 'MinimalProvider';
  getApiKeyLink = 'https://minimal.example.com/keys';

  config = {
    apiTokenKey: 'MINIMAL_API_KEY',
    baseUrl: 'https://api.minimal.example.com/v1',
  };

  staticModels: ModelInfo[] = [
    {
      name: 'minimal-v1',
      label: 'Minimal V1',
      provider: 'MinimalProvider',
      maxTokenAllowed: 32000,
      maxCompletionTokens: 4096,
    },
  ];

  getModelInstance(options: {
    model: string;
    serverEnv: Env;
    apiKeys?: Record<string, string>;
    providerSettings?: Record<string, IProviderSetting>;
  }): any {
    const { apiKey } = this.getProviderBaseUrlAndKey({
      apiKeys: options.apiKeys,
      providerSettings: options.providerSettings?.[this.name],
      serverEnv: options.serverEnv as any,
      defaultBaseUrlKey: '',
      defaultApiTokenKey: 'MINIMAL_API_KEY',
    });

    if (!apiKey) {
      throw new Error(`Missing API key for ${this.name}`);
    }

    const openai = createOpenAI({
      baseURL: this.config.baseUrl!,
      apiKey,
    });

    return openai(options.model);
  }
}
```

This provider will immediately appear in the model selector once registered in `registry.ts`.
