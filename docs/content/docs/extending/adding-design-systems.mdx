---
title: Adding a New Design System
description: How to create and register visual design systems for Amplify's AI
---

Design systems provide visual guidelines that the AI follows when creating UI components and pages. Amplify ships with dozens of built-in design systems (Apple, Stripe, Notion, etc.) and supports custom systems through auto-discovery.

## Overview

Amplify's design system architecture:

- **`design/design-systems/`** — directory containing all design systems
- **`DESIGN.md`** — the core file in each system's directory
- **`SkillLoader._loadDesignSystems()`** — auto-discovery that scans the directory at startup
- Each system is a subdirectory with a single `DESIGN.md` file

## Creating a Design System

### 1. Create the Directory

```bash
mkdir -p design/design-systems/your-system
```

Use a short, descriptive name for the directory. Existing examples include: `apple`, `stripe`, `notion`, `airbnb`, `spacex`, `clean`, `futuristic`, etc.

### 2. Create DESIGN.md

Create `design/design-systems/your-system/DESIGN.md` with structured visual guidelines:

```markdown
# Design System Inspired by Your System Name

> Category: Your Category
> A brief one-line summary of the design system's mood and purpose.

## Visual Theme & Atmosphere
Describe the overall feeling: e.g., "Warm, inviting, community-focused. Soft edges, generous spacing, personal touch."

## Color Palette & Roles
- **Background:** `#hex` — describe usage
- **Foreground:** `#hex` — describe usage
- **Accent:** `#hex` — describe usage (primary CTAs, links)
- **Muted:** `#hex` — describe usage (secondary text, captions)
- **Border:** `#hex` — describe usage
- **Surface:** `#hex` — describe usage (cards, modals)
- **Success:** `#hex`, **Warn:** `#hex`, **Danger:** `#hex`
Rules about color usage (e.g., "Never use accent color for large areas").

## Typography Rules
- **Display / headings:** `'Font Name', fallback, category`, weight X
- **Body:** `'Font Name', fallback, category`, weight X
- **Mono:** `monospace stack`, weight X
- Scale (px): list all allowed sizes
- Line-height: values for body and headings
- Letter-spacing: rules for different sizes

## Component Stylings
- **Buttons:** radius, padding, variants (primary, secondary, ghost)
- **Cards:** background, border, radius, padding, shadow rules
- **Inputs:** border, radius, padding, focus state
- **Links:** color, underline behavior

## Layout Principles
- Grid system (columns, max-width, gutters)
- Hero section guidelines
- Section spacing rules
- Whitespace philosophy

## Depth & Elevation
List elevation levels with their visual treatment:
- **Flat (0):** default
- **Raised (1):** description of shadow/offset

## Do's and Don'ts
- ✅ Positive guidelines
- ✅ More positive guidelines
- ❌ Things to avoid
- ❌ More things to avoid

## Responsive Behavior
- Desktop breakpoints and grid
- Tablet breakpoints and grid
- Phone breakpoints and grid

## Agent Prompt Guide
- Key instructions for the AI when applying this system
- What to prioritize, what to avoid
- Edge cases and special rules
```

### 3. Auto-Discovery

The `SkillLoader._loadDesignSystems()` method automatically discovers your system at startup:

1. Scans `design/design-systems/` for all subdirectories
2. Reads `DESIGN.md` from each directory
3. Parses the title from the `# Heading` line
4. Parses the category from `> Category:` lines
5. Parses the summary from the line after `> Category:`
6. Registers the system in an internal `Map<string, DesignSystemEntry>`

No manual registration is needed — just create the directory and `DESIGN.md` file.

### 4. DESIGN.md Format Requirements

Your `DESIGN.md` must follow these structural rules for proper auto-discovery:

#### Required Elements

| Element | Format | Purpose |
|---------|--------|---------|
| **Title** | `# Design System Inspired by X` or `# X` | Used as the display label |
| **Category** | `> Category: CategoryName` | Groups systems in the UI |
| **Summary** | `> Brief description` (line after category) | Short description shown in selection |

#### Category Options

Common categories used in existing design systems:

| Category | Examples |
|----------|---------|
| **Starter** | `default`, `clean`, `simple` |
| **Professional** | `stripe`, `intercom`, `hashicorp` |
| **Enterprise** | `ibm`, `enterprise`, `corporate` |
| **Creative** | `artistic`, `doodle`, `fantasy` |
| **Minimal** | `minimal`, `mono`, `flat` |
| **Luxury** | `luxury`, `ferrari`, `bugatti` |
| **Tech** | `raycast`, `vercel`, `sentry` |
| **Playful** | `duolingo`, `pacman`, `tetris` |
| **Dark** | `warp`, `linear-app`, `mission-control` |

#### Title Parsing

The loader extracts the label from the title line:

```
"# Design System Inspired by Stripe" → "Stripe"
"# Design System Inspired by Apple" → "Apple"
"# Neutral Modern" → "Neutral Modern"
```

If the title starts with "Design System Inspired by", that prefix is stripped. Otherwise, the full title is used as the label.

### 5. Content Guidelines

Write design guidelines that the AI can follow precisely:

#### Be Specific with Hex Values

```markdown
## Color Palette
- **Accent:** `#2F6FEB` — used ONLY for primary CTAs and one hero element per screen
```

Don't write vague descriptions like "use a blue accent." The AI needs exact hex values.

#### Include Negative Rules

```markdown
## Do's and Don'ts
- ❌ No gradients (except hero accent sparingly)
- ❌ No drop shadows on inputs
- ❌ No more than three type sizes on one screen
```

Negative rules prevent the AI from making common design mistakes.

#### Define Component Variants

```markdown
## Component Stylings
- **Buttons:**
  - Primary: cobalt fill, white label, 8px radius
  - Secondary: 1px cobalt border, transparent fill, cobalt label
  - Ghost: no border, no fill, cobalt label only
```

#### Specify Responsive Behavior

The AI needs concrete breakpoints and grid rules:

```markdown
## Responsive Behavior
- **Desktop ≥ 1024px:** 12-col grid, 24px gutters
- **Tablet 640–1023px:** 8-col grid, 16px gutters
- **Phone < 640px:** 4-col grid, 12px gutters
```

## Examples from Existing Design Systems

### Apple (Minimal, Premium)

```markdown
# Design System Inspired by Apple

> Category: Minimal
> Ultra-minimal, premium aesthetic. White space is the primary design element.

## Visual Theme & Atmosphere
Sparse, precise, obsessively refined. Nothing extra. Every element earns its place.

## Color Palette & Roles
- **Background:** `#F5F5F7`
- **Foreground:** `#1D1D1F`
- **Accent:** `#0071E3` — one link, one button per screen
- **Muted:** `#86868B`
- **Border:** `#D2D2D7`
- **Surface:** `#FFFFFF`

## Typography Rules
- **Display:** `SF Pro Display`, weight 600
- **Body:** `SF Pro Text`, weight 400
- Scale: 14 · 17 · 21 · 28 · 40 · 56
- Letter-spacing: -0.02em on ≥40px

## Component Stylings
- **Buttons:** pill-shaped (full radius), generous padding, no borders on primary
- **Cards:** no visible border, subtle shadow only on hover

## Do's and Don'ts
- ✅ Let whitespace dominate — 60%+ of any screen should be empty
- ❌ Never use more than one accent color element per viewport
- ❌ Never use decorative borders or dividers
```

# Design System Inspired by Stripe

> Category: Professional

## Visual Theme & Atmosphere
Calm authority. Information-rich but never cluttered. Every pixel serves the user.

## Color Palette & Roles
- **Background:** `#F6F9FC`
- **Foreground:** `#1A1F36`
- **Accent:** `#635BFF` — primary actions, active states
- **Muted:** `#8898AA`

- **Buttons:** 6px radius, 12px vertical padding, subtle shadow on primary

```markdown
# Design System Inspired by Futuristic

> Category: Creative
> Sci-fi meets reality. Glowing edges, dark surfaces, neon accents. For bold tech products.

## Visual Theme & Atmosphere
Immersive, high-tech, borderline cinematic. Dark surfaces with glowing accents.

## Color Palette & Roles
- **Background:** `#0A0A0F`
- **Foreground:** `#E8E8ED`
- **Accent:** `#00E5FF` — neon cyan for interactive elements
- **Muted:** `#6B6B80`
- **Border:** `#1A1A2E`
- **Surface:** `#141420`
- **Accent2:** `#7C3AED` — secondary glow (purple)

## Depth & Elevation
- **Flat (0):** default dark surface
- **Raised (1):** subtle glow border + shadow

## Do's and Don'ts
- ✅ Use glowing borders as the primary elevation indicator
- ✅ Dark backgrounds with neon accents for energy
- ❌ Never use white backgrounds
- ❌ Never use flat solid borders — always add glow
```

## Verification

After creating your design system, verify it's discovered:

1. Restart the Amplify server
2. Check server logs for: `Loaded X total skills, Y design systems`
3. Open a chat and ask the AI to use your design system
4. The AI should load your `DESIGN.md` content and follow its guidelines

## Design System Selection in Chat

When a user asks the AI to "build a dashboard using the Stripe design system," the AI:

1. Looks up the system by name in `SkillLoader._designSystems`
2. Calls `getDesignSystemContent('stripe')` to load the full `DESIGN.md`
3. Includes the guidelines in its context
4. Applies the visual rules when generating code

The design system content is loaded on-demand (not at startup) to conserve the AI's context window.
