Amplify supports the [Model Context Protocol](https://modelcontextprotocol.io/) (MCP), which allows you to connect external tool servers that the AI can invoke during conversations. MCP servers extend Amplify's capabilities by providing specialized tools for file systems, databases, APIs, and more.

## UI-Driven Configuration

The easiest way to add MCP servers is through the Settings UI:

1. Open **Settings** (gear icon in the sidebar)
2. Navigate to the **MCP** tab
3. Click **Add Server**
4. Fill in the server configuration
5. Click **Connect**

The MCP tab shows:
- Connected servers with their status (green = connected, red = error)
- Available tools for each server
- Add/remove controls

## Transport Types

Amplify supports three MCP transport types:

### 1. Stdio Transport

The most common transport for local MCP servers. The server runs as a subprocess and communicates via stdin/stdout.

```json
{
  "mcpServers": {
    "filesystem": {
      "command": "npx",
      "args": ["-y", "@modelcontextprotocol/server-filesystem", "/home/user/projects"],
      "env": {
        "NODE_ENV": "production"
      }
    }
  }
}
```

**Configuration fields:**

| Field | Required | Description |
|-------|----------|-------------|
| `command` | Yes | The command to run (e.g., `npx`, `python`, `node`) |
| `args` | No | Arguments passed to the command |
| `env` | No | Environment variables for the subprocess |
| `cwd` | No | Working directory for the subprocess |
| `type` | No | Defaults to `"stdio"` if omitted |

### 2. SSE Transport

For remote MCP servers that expose a Server-Sent Events endpoint. Useful for cloud-hosted servers.

```json
{
  "mcpServers": {
    "remote-search": {
      "type": "sse",
      "url": "https://mcp-server.example.com/sse",
      "headers": {
        "Authorization": "Bearer your-token-here"
      }
    }
  }
}
```

**Configuration fields:**

| Field | Required | Description |
|-------|----------|-------------|
| `url` | Yes | The SSE endpoint URL |
| `headers` | No | HTTP headers sent with requests (e.g., auth) |
| `type` | Yes | Must be `"sse"` |

### 3. Streamable HTTP Transport

For remote MCP servers that use the newer streamable HTTP transport. This is the recommended transport for remote servers.

```json
{
  "mcpServers": {
    "remote-api": {
      "type": "streamable-http",
      "url": "https://mcp-server.example.com/mcp",
      "headers": {
        "Authorization": "Bearer your-token-here"
      }
    }
  }
}
```

**Configuration fields:**

| Field | Required | Description |
|-------|----------|-------------|
| `url` | Yes | The MCP endpoint URL |
| `headers` | No | HTTP headers sent with requests (e.g., auth) |
| `type` | Yes | Must be `"streamable-http"` |

## Configuration Storage

MCP configuration is stored in the browser's `localStorage` and synced to the server via the `/api/mcp-update-config` endpoint. This allows the server-side `MCPService` to connect to the same servers for tool invocation during chat sessions.

The flow is:

1. User adds server in the Settings UI
2. Config is saved to `localStorage` in the browser
3. Config is sent to `/api/mcp-update-config` via POST
4. Server-side `MCPService.updateConfig()` connects to the new servers
5. Available tools are returned and displayed in the UI

## Tool Discovery and Registration

When an MCP server is connected, Amplify automatically:

1. Creates an MCP client for the server
2. Calls `client.listTools()` to discover available tools
3. Registers each tool in the `MCPService._tools` registry
4. Makes the tools available to the AI during chat sessions

The AI sees all registered tools (both native Amplify tools and MCP tools) in its tool list. When the AI calls an MCP tool, the `MCPService` routes the call to the appropriate server.

## Example MCP Server Configurations

### Filesystem Server

Provides read/write access to local directories:

```json
{
  "mcpServers": {
    "filesystem": {
      "command": "npx",
      "args": ["-y", "@modelcontextprotocol/server-filesystem", "/home/user/documents", "/home/user/projects"]
    }
  }
}
```

Tools provided: `read_file`, `write_file`, `list_directory`, `search_files`, `create_directory`, `move_file`

### GitHub Server

Interact with GitHub repositories:

```json
{
  "mcpServers": {
    "github": {
      "command": "npx",
      "args": ["-y", "@modelcontextprotocol/server-github"],
      "env": {
        "GITHUB_PERSONAL_ACCESS_TOKEN": "ghp_your-token-here"
      }
    }
  }
}
```

Tools provided: `create_or_update_file`, `search_repositories`, `get_file_contents`, `create_issue`, `list_commits`

### PostgreSQL Server

Query and explore PostgreSQL databases:

```json
{
  "mcpServers": {
    "postgres": {
      "command": "npx",
      "args": ["-y", "@modelcontextprotocol/server-postgres", "postgresql://user:pass@localhost:5432/mydb"]
    }
  }
}
```

Tools provided: `query`, `list_tables`, `describe_table`

### Brave Search Server

Web search via Brave Search API:

```json
{
  "mcpServers": {
    "brave-search": {
      "command": "npx",
      "args": ["-y", "@modelcontextprotocol/server-brave-search"],
      "env": {
        "BRAVE_API_KEY": "your-brave-api-key"
      }
    }
  }
}
```

Tools provided: `brave_web_search`, `brave_local_search`

### Memory Server

Persistent key-value memory for the AI:

```json
{
  "mcpServers": {
    "memory": {
      "command": "npx",
      "args": ["-y", "@modelcontextprotocol/server-memory"]
    }
  }
}
```

Tools provided: `add_memory`, `search_memories`, `delete_memory`

### Puppeteer Server

Browser automation for testing and scraping:

```json
{
  "mcpServers": {
    "puppeteer": {
      "command": "npx",
      "args": ["-y", "@modelcontextprotocol/server-puppeteer"]
    }
  }
}
```

Tools provided: `puppeteer_navigate`, `puppeteer_click`, `puppeteer_screenshot`, `puppeteer_fill`

### Custom Python MCP Server

For custom MCP servers written in Python:

```json
{
  "mcpServers": {
    "custom-python": {
      "command": "python",
      "args": ["-m", "my_mcp_server"],
      "env": {
        "API_KEY": "your-api-key"
      }
    }
  }
}
```

## Troubleshooting MCP Connections

### Server Won't Connect

**Check the command is correct:**

```bash
# Test that the command runs manually
npx -y @modelcontextprotocol/server-filesystem /tmp/test
```

**Check environment variables:**

Ensure any required env vars (API keys, tokens) are included in the `env` field of the configuration.

**Check the URL for SSE/HTTP servers:**

- URLs must be valid and reachable
- Include any required auth headers
- Some servers require specific URL paths (e.g., `/sse` vs `/mcp`)

### Docker Environment

When running Amplify in Docker, MCP servers that reference `localhost` need special handling:

- For stdio servers: the server command runs inside the Docker container, so it can only access the container's filesystem
- For SSE/HTTP servers: use `host.docker.internal` instead of `localhost` to reach services on the host machine

### Tool Not Showing Up

If a connected server's tools don't appear:

1. Check the server logs for errors
2. Verify the server implements the MCP protocol correctly
3. Try reconnecting via the Settings UI
4. Check that the `MCPService` is initialized (it should show in server logs at startup)

### Timeout Issues

MCP tool calls have timeouts. If a tool takes too long:

1. Check if the server is overloaded
2. Consider increasing timeout settings
3. Ensure the server's response format matches MCP expectations

### Multiple Servers Conflicting

If two MCP servers provide tools with the same name, the `MCPService` maps each tool to its source server. The AI's tool call includes the server name to route correctly. However, if the AI gets confused, consider:

1. Using distinct server names
2. Disabling overlapping tools in one server
3. Removing redundant servers
