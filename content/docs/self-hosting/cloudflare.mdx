# Cloudflare Pages Deployment

Amplify is designed for Cloudflare Pages deployment using Remix v2 and Wrangler. This is the deployment method used for the official hosted version of Amplify.

## Prerequisites

- A Cloudflare account
- Wrangler CLI installed (`npm install -g wrangler`)
- The project built and ready for deployment

## Configuration

The `wrangler.toml` file contains the Cloudflare configuration:

```toml
name = "amplify"
compatibility_flags = ["nodejs_compat"]
compatibility_date = "2025-03-28"
pages_build_output_dir = "./build/client"
send_metrics = false
```

### Key Settings

| Setting | Value | Purpose |
|---------|-------|---------|
| `name` | `amplify` | Project name on Cloudflare |
| `compatibility_flags` | `nodejs_compat` | Enable Node.js APIs in Workers runtime |
| `compatibility_date` | `2025-03-28` | Latest runtime feature compatibility |
| `pages_build_output_dir` | `./build/client` | Remix SSR build output directory |
| `send_metrics` | `false` | Disable Wrangler telemetry |

## Deployment Steps

### Build the Application

```bash
# Build the Remix app (SSR + client)
pnpm run build
```

This creates:
- `build/client/` — Client-side assets (HTML, JS, CSS)
- `build/server/` — Server-side Remix bundle

### Deploy to Cloudflare Pages

```bash
# Deploy directly
pnpm run deploy
```

Or manually:

```bash
wrangler pages deploy ./build/client
```

### Set Environment Variables

Cloudflare Pages environment variables are configured via the Cloudflare dashboard or Wrangler:

```bash
# Set secrets (API keys)
wrangler pages secret put OPENAI_API_KEY
wrangler pages secret put ANTHROPIC_API_KEY

# Set non-secret variables
wrangler pages config set DEFAULT_NUM_CTX=32768
```

Or via the Cloudflare Dashboard:
1. Go to Workers & Pages → your project → Settings → Environment variables
2. Add each API key as a secret
3. Add runtime configuration as plain text variables

## Cloudflare Workers Bindings

The `bindings.sh` script generates Wrangler bindings from environment variables for local development:

```bash
# Start with bindings
bindings=$(./bindings.sh) && wrangler pages dev ./build/client $bindings
```

This script reads your `.env.local` and converts the variables into Wrangler command-line arguments, making them available in the Workers runtime during local development.

## Cross-Origin Headers

WebContainers require specific Cross-Origin headers. On Cloudflare Pages, add a `_headers` file in the `public/` directory:

```
/*
  Cross-Origin-Embedder-Policy: credentialless
  Cross-Origin-Opener-Policy: same-origin
```

This file is copied to the build output during the Remix build process and served by Cloudflare Pages alongside your application.

## Custom Domain

To use a custom domain with your Cloudflare Pages deployment:

1. Go to Workers & Pages → your project → Custom domains
2. Add your domain (e.g., `amplify.example.com`)
3. Cloudflare handles DNS and SSL automatically

Or via Wrangler:

```bash
wrangler pages project custom-domain amplify example.com
```

## Production Considerations

### Worker Size Limits

Cloudflare Workers have size limits:
- **Free plan** — 1 MB worker size
- **Paid plan** — 10 MB worker size

Amplify's server bundle includes the Vercel AI SDK and all provider SDKs, which can be large. If you encounter size limit errors:

1. Ensure only production dependencies are included (`pnpm prune --prod`)
2. Check the bundle size with `wrangler pages deploy --dry-run`
3. Consider upgrading to a paid Cloudflare plan

### Request Limits

Cloudflare Workers limits per request:
- **CPU time** — 10 ms (free), 30 ms (bundled), 30 seconds (unbound)
- **Subrequest count** — 50 per request (for LLM API calls)
- **Request size** — 100 MB

Most chat interactions stay well within these limits. Streaming responses use a single subrequest to the LLM provider.

### Edge Compatibility

Amplify uses `nodejs_compat` flag to enable Node.js APIs in the Workers runtime. This provides:
- `process.env` — Access to environment variables and secrets
- `Buffer` — Binary data handling
- `crypto` — Cryptographic operations
- `stream` — Readable/Writable streams for SSE

Some Node.js APIs may have limitations in the edge runtime. Check the Cloudflare compatibility docs for specifics.

## Local Development with Cloudflare

```bash
# Start the Cloudflare Pages dev server locally
pnpm run start:unix
# or on Windows:
pnpm run start:windows
```

This runs `wrangler pages dev` with the built client output and bindings from your `.env.local` file.

### Differences from Regular Dev Mode

| Feature | `pnpm run dev` | `pnpm run start` |
|---------|----------------|-------------------|
| Runtime | Node.js (Vite) | Cloudflare Workers (Wrangler) |
| HMR | Yes | No (requires rebuild) |
| Bindings | .env.local | Wrangler bindings |
| API compatibility | Full Node.js | Edge + nodejs_compat |

Use `pnpm run dev` for active development (with HMR and hot reload). Use `pnpm run start` for testing the production-like Cloudflare runtime.

## Monitoring and Analytics

Cloudflare provides built-in monitoring:
- **Web Analytics** — Page views, performance metrics
- **Workers Analytics** — Request counts, error rates, CPU time
- **Real-time logs** — `wrangler pages deployment tail`

For Amplify-specific monitoring:
- `/api/health` — Application health endpoint
- `/api/system/diagnostics` — Detailed system diagnostics

## Troubleshooting Cloudflare

| Issue | Solution |
|-------|----------|
| Worker size too large | Prune dev deps; use paid plan |
| COEP headers missing | Add `_headers` file in public/ |
| API keys not available | Set secrets via Wrangler or dashboard |
| nodejs_compat errors | Check compatibility_date and flags |
| Streaming not working | Ensure SSE headers are correct |
