# Amplify Documentation

Amplify is an open-source AI-powered coding environment that lets you build, run, and deploy full-stack applications directly in your browser. It supports **22+ LLM providers**, **Model Context Protocol (MCP)** for extensibility, **Orama vector database** for intelligent context management, and **WebContainer sandboxing** for secure in-browser execution.

## Key Features

- **22+ LLM Providers** — From OpenAI and Anthropic to local providers like Ollama and LM Studio, Amplify supports a wide range of language model backends through the Vercel AI SDK v7.
- **Model Context Protocol (MCP)** — Connect external tools and data sources to your AI workspace through standardized MCP servers (stdio, SSE, and Streamable HTTP transports).
- **Vector Database** — Orama-powered full-text search with BM25 ranking, providing intelligent project context and user profile memory that persists across sessions.
- **WebContainer Sandboxing** — Run Node.js environments directly in the browser with StackBlitz WebContainers — no server required, fully sandboxed execution.
- **Planning System** — Break complex tasks into sequential sub-chats with verification checkpoints, dramatically reducing token consumption while maintaining coherence.
- **Native Copilot Tools** — File operations (read, write, search, grep) modeled after VSCode Copilot's built-in toolset, operating on the browser-side file system.
- **Skill System** — Extensible skill framework that injects domain-specific knowledge (React best practices, API integration, mobile development, etc.) into AI context.
- **Multi-Deploy** — Deploy to Vercel, Netlify, GitHub Pages, GitLab, and more directly from the workbench.

## Architecture Overview

Amplify is built on **Remix v2** with **Vite** for the frontend, deploying to **Cloudflare Pages** via Wrangler. The LLM pipeline uses the **Vercel AI SDK v7** with a provider registry pattern that supports dynamic model discovery. State management uses **Zustand** and **Nanostores** for reactive client-side stores, with **IndexedDB** for persistence.

The system follows a client-server architecture where:

- The **server** (Cloudflare Workers / Remix) handles LLM API calls, tool routing, and MCP orchestration
- The **client** (browser) manages WebContainer execution, file operations, workbench UI, and vector store persistence
- Mutating tool operations return structured **mutation signals** that the client applies to the workbench file store
