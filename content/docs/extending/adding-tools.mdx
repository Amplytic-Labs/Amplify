# Adding Tools

Amplify supports two types of tools: **native tools** (built into Amplify) and **MCP tools** (provided by external MCP servers). This guide covers creating both types.

## MCP Server Tools

The most common way to add tools is by connecting MCP servers that provide specialized functionality. You can use existing MCP servers or create your own.

### Using Existing MCP Servers

Many MCP servers are already available as npm packages:

```bash
# Install and configure a filesystem MCP server
npx -y @modelcontextprotocol/server-filesystem /path/to/dir
```

See [MCP Integration](/docs/integrations/mcp) for a full list of popular servers and configuration details.

### Creating a Custom MCP Server

To create your own MCP server that provides tools to Amplify:

#### Step 1: Set Up the MCP Server Project

```bash
# Create a new MCP server project
mkdir my-mcp-server
cd my-mcp-server
npm init -y

# Install MCP SDK
npm install @modelcontextprotocol/sdk
```

#### Step 2: Implement the Server

Create a stdio-based MCP server:

```typescript
// server.ts
import { Server } from '@modelcontextprotocol/sdk/server/index.js';
import { StdioServerTransport } from '@modelcontextprotocol/sdk/server/stdio.js';

const server = new Server(
  {
    name: 'my-custom-tools',
    version: '1.0.0',
  },
  {
    capabilities: {
      tools: {},
    },
  },
);

// Register a tool
server.setRequestHandler('tools/list', async () => ({
  tools: [
    {
      name: 'my_custom_tool',
      description: 'A custom tool that does something useful',
      inputSchema: {
        type: 'object',
        properties: {
          input: {
            type: 'string',
            description: 'The input to process',
          },
        },
        required: ['input'],
      },
    },
  ],
}));

// Handle tool execution
server.setRequestHandler('tools/call', async (request) => {
  if (request.params.name === 'my_custom_tool') {
    const input = request.params.arguments.input;
    
    // Your tool logic here
    const result = processInput(input);
    
    return {
      content: [
        {
          type: 'text',
          text: JSON.stringify(result),
        },
      ],
    };
  }
  
  throw new Error('Unknown tool');
});

// Start the server
const transport = new StdioServerTransport();
await server.connect(transport);
```

#### Step 3: Configure in Amplify

Add the MCP server to Amplify's configuration:

```json
{
  "mcpServers": {
    "my-custom-tools": {
      "type": "stdio",
      "command": "node",
      "args": ["server.js"],
      "cwd": "/path/to/my-mcp-server",
      "env": {
        "MY_API_KEY": "optional-api-key"
      }
    }
  }
}
```

Or add via the Settings panel → MCP → Add Server.

### Creating an SSE MCP Server

For remote MCP servers, use SSE transport:

```typescript
// sse-server.ts
import { Server } from '@modelcontextprotocol/sdk/server/index.js';
import { SSEServerTransport } from '@modelcontextprotocol/sdk/server/sse.js';
import express from 'express';

const app = express();
const server = new Server(
  { name: 'my-remote-tools', version: '1.0.0' },
  { capabilities: { tools: {} } },
);

// Same tool registration as stdio server
server.setRequestHandler('tools/list', async () => ({
  tools: [
    {
      name: 'remote_tool',
      description: 'A remote tool via SSE',
      inputSchema: {
        type: 'object',
        properties: {
          query: { type: 'string', description: 'Search query' },
        },
        required: ['query'],
      },
    },
  ],
}));

server.setRequestHandler('tools/call', async (request) => {
  // Tool logic
  return { content: [{ type: 'text', text: 'Result' }] };
});

// SSE endpoint
app.get('/sse', async (req, res) => {
  const transport = new SSEServerTransport('/messages', res);
  await server.connect(transport);
});

app.post('/messages', async (req, res) => {
  // Handle client-to-server messages
});

app.listen(3001);
```

Configure in Amplify:

```json
{
  "mcpServers": {
    "my-remote-tools": {
      "type": "sse",
      "url": "https://my-server.com/sse",
      "headers": {"Authorization": "Bearer token"}
    }
  }
}
```

## Native Tools

Native tools are built into Amplify and operate on the project file system. Adding a new native tool requires modifying the `nativeTools.ts` file.

### When to Add a Native Tool

Add a native tool when:
- The tool operates on the project's file map (like read_file, grep_search)
- The tool needs to be available without external dependencies
- The tool returns mutation signals that the workbench applies

### Step 1: Define the Tool Schema

Add a new tool definition in `nativeTools.ts`:

```typescript
const myNewTool = {
  name: 'my_new_tool',
  description: 'A tool that performs a specific operation on project files',
  parameters: z.object({
    path: z.string().describe('File path to operate on'),
    option: z.enum(['a', 'b', 'c']).describe('Operation option'),
  }),
};
```

### Step 2: Implement the Execute Function

```typescript
async function executeMyNewTool(
  args: { path: string; option: string },
  context: NativeToolContext,
): Promise<string> {
  const { path, option } = args;
  const { files } = context;

  // Get the file from the map
  const file = getFileFromMap(files, path);
  
  if (!file) {
    return `Error: File not found at ${path}`;
  }

  // Perform the operation
  const result = performOperation(file.content, option);

  // For read-only operations, return the result directly
  return result;

  // For mutating operations, return a mutation signal
  // return JSON.stringify({ type: 'mutation', action: 'my_new_tool', ... });
}
```

### Step 3: Register the Tool

Add the tool to the tool builder:

```typescript
export function buildNativeTools(context: NativeToolContext) {
  return [
    // ... existing tools
    {
      name: 'my_new_tool',
      description: myNewTool.description,
      parameters: myNewTool.parameters,
      execute: (args) => executeMyNewTool(args as any, context),
    },
  ];
}
```

### Step 4: Add Mutation Handling (For Mutating Tools)

If your tool modifies files, add a mutation signal handler in `Chat.client.tsx`:

```typescript
// In the tool result processing logic
if (toolResult.type === 'mutation' && toolResult.action === 'my_new_tool') {
  // Apply the mutation to the workbench
  workbenchStore.applyMyNewToolMutation(toolResult);
}
```

## Tool Design Guidelines

### Keep Tools Simple

Each tool should do one thing well. Avoid creating tools with complex multi-step logic.

### Use Descriptive Names

Tool names should clearly describe what they do:
- `read_file` ✓ — Clear and specific
- `do_stuff` ✗ — Vague and unclear

### Provide Good Descriptions

Tool descriptions help the AI understand when to use them. Include:
- What the tool does
- When to use it
- What the expected output format is

### Validate Input with Zod

Always use Zod schemas for parameter validation. This prevents runtime errors from malformed tool calls.

### Handle Errors Gracefully

Return meaningful error messages instead of throwing exceptions. The AI can adapt its approach based on the error:

```typescript
if (!file) {
  return `Error: File "${path}" not found in the project. Available files: ${listAvailableFiles(files)}`;
}
```

## Tool Categories

### Read-Only Tools

These tools only read data and return results:
- `read_file` — Read file contents
- `list_dir` — List directory contents
- `find_files` — Search for files by name
- `grep_search` — Search for text patterns
- `web_search` — Search the web

Read-only tools operate on the file map sent with the request. No mutation signals needed.

### Mutating Tools

These tools modify files and return mutation signals:
- `create_file` — Create new files
- `replace_string_in_file` — Replace strings in files
- `multi_replace_string_in_file` — Multiple replacements

Mutating tools must follow the mutation signal pattern to ensure changes are applied through the workbench store.

### External Tools (MCP)

These tools connect to external services:
- Database queries (PostgreSQL, MySQL)
- API calls (GitHub, Brave Search)
- Browser automation (Puppeteer)
- Cloud services (AWS, GCP)

MCP tools are managed by the MCP service and don't require native tool modifications.

## Testing Tools

### Manual Testing

Test tools by invoking them in a chat session:
1. Configure the MCP server or enable the native tool
2. Ask the AI to use the tool in a message
3. Verify the tool executes correctly
4. Check the result appears in the chat

### API Testing

Test MCP connectivity via the API:

```bash
curl -X POST http://localhost:5173/api/mcp-check \
  -H "Content-Type: application/json" \
  -d '{"serverName": "my-server", "config": {...}}'
```

### Unit Testing

Write unit tests for native tools:

```typescript
// nativeTools.spec.ts
describe('my_new_tool', () => {
  it('should process files correctly', () => {
    const result = executeMyNewTool(
      { path: 'test.ts', option: 'a' },
      { files: { 'test.ts': { type: 'file', content: '...' } } },
    );
    expect(result).toContain('expected output');
  });
});
```
