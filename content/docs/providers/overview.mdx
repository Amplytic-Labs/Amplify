# Provider Overview

Amplify supports **22+ LLM providers** through a unified provider registry built on the Vercel AI SDK v7. This architecture allows you to switch between providers and models seamlessly while maintaining consistent tool support and streaming behavior.

## Provider Registration

All providers are registered at startup through the `LLMManager` singleton:

1. The `registry.ts` file exports all provider classes
2. Each class extends `BaseProvider` (the abstract base)
3. `LLMManager._registerProvidersFromDirectory()` iterates over all exports
4. Classes that extend `BaseProvider` are instantiated and registered
5. Provider names are used as keys in the `_providers` Map

### BaseProvider Contract

Every provider must implement:

- `name` — Unique provider identifier string
- `staticModels` — Array of well-known model definitions
- `config` — API key name, base URL key, and defaults
- `getModelInstance()` — Creates a Vercel AI SDK LanguageModel

Optional methods:
- `getDynamicModels()` — Fetches live model catalog from the provider
- `getApiKeyLink` — URL where users can obtain an API key
- `labelForGetApiKey` — Human-readable label for the link

## Model Discovery

Models are discovered through two mechanisms:

### Static Models

Every provider defines a `staticModels` array of well-known, stable models. These are always available regardless of API connectivity and serve as fallbacks when dynamic discovery fails.

### Dynamic Models

Providers that support dynamic discovery fetch their model catalog from the provider's API at runtime. This is triggered when the user opens the model selector.

Dynamic discovery:
1. Uses the configured API key to authenticate
2. Fetches `/v1/models` (or provider-specific endpoint)
3. Maps response to `ModelInfo` format
4. Caches results with a `cacheId` based on the API key
5. Has a 5-second timeout to prevent hanging
6. Falls back to static models on failure

## Model Selection

When a user selects a model:

1. The provider name and model ID are sent with the chat request
2. `LLMManager` resolves the provider from the registry
3. The provider's `getModelInstance()` creates a Vercel AI SDK `LanguageModel`
4. API keys and base URLs are resolved from environment variables and client settings
5. The model instance is used for the streaming chat response

## Configuring Providers

### Via Environment Variables

Server-side API keys are configured via environment variables (`.env.local` or Docker env):

```bash
OPENAI_API_KEY=sk-your-key
ANTHROPIC_API_KEY=sk-ant-your-key
```

### Via Settings Panel

Client-side API keys are configured in the Settings panel and stored in localStorage:
1. Open Settings → Providers → Cloud Providers tab
2. Enter your API key for each provider
3. Click "Test Connection" to verify connectivity
4. Keys are sent with every `/api/chat` request

### Custom Base URLs

Local providers and OpenAI-like providers support custom base URLs:
1. Open Settings → Providers → Local Providers tab
2. Set the base URL for Ollama, LM Studio, or OpenAI-like
3. URLs pointing to `localhost` are auto-rewritten for Docker

## Adding Custom Providers

You can add custom OpenAI-compatible providers via the "Add Provider" popup:
1. Click the "+" button in the provider settings
2. Enter a custom name, base URL, and API key
3. Models are discovered dynamically from the custom endpoint
4. The provider appears in the model selector

See [Adding Providers](/docs/extending/adding-providers) for details on implementing new provider classes.
